# Identra 使用手册

> 指纹浏览器 + Generic AI Browser Operator 控制台。安装与一键启动见仓库根 [README.md](../README.md)；本文只讲「每个面板怎么用、出问题去哪查」。

## 0. 界面导航（C86 AI Workspace）

侧栏分四组；顶栏右侧常驻 Workspace Health 健康 pill（`● All systems operational` = 一切正常，点击进完整自检页）与 **New Task** 主按钮（一句话描述目标 → 生成计划 → 一键执行）。

| 分组 | 面板 | 说明 |
| --- | --- | --- |
| Workspace | **Overview** | 新首页：AI 正在做什么 / 完成多少 / 需要关注什么 |
| Workspace | **Tasks** | 自动化任务管理（旧「自动化任务」） |
| Workspace | **Runs** | 执行队列与运行记录（旧「执行引擎」） |
| Workspace | **Browser Profiles** | 浏览器环境与指纹配置（旧「配置管理」） |
| Automation | **AI Operator** | 给 AI 一个目标，它来执行（三栏：Goal / 执行态 / AI Activity） |
| Automation | **Schedules** | 定时自动执行（旧「定时调度」） |
| Automation | **Templates** | 指纹模板库 |
| Insights | **Activity** | 执行轨迹与事件流（旧 Observability） |
| Insights | **Memory** | 站点画像与经验记忆（旧「智能记忆」） |
| System | **Proxies** | 代理资源接入 |
| System | **Governance** | 密钥、审计与协作 |
| System | **Settings** | 系统配置 |

状态语言对照：`AI 自修复中`（HEALING）/ `需要你确认`（PAUSED_FOR_HUMAN）/ `执行中`（RUNNING）；时间线中 teal 色「AI 已自动恢复」表示 AI 遇到页面变化后自动重新定位并继续执行，无需人工介入。

### 0.1 创建一个 AI 任务（Goal-first）

点顶栏 **New Task**，整个弹窗第一步只有一个问题：**「你希望 AI 做什么？」**——用一句自然语言描述目标即可，例如「打开 xxx.com，注册一个新账号并登录，完成后告诉我结果」。

1. **描述目标** → 点「生成计划」（或 ⌘/Ctrl + Enter）。AI 会把你的目标拆成带风险标注的分步计划。
2. **预览计划** → 每一步右侧标注风险：`LOW` 灰色（浏览/点击类）；`HIGH` / `CRITICAL` 琥珀色（涉及提交、支付、删除等高风险动作）。不满意点「返回修改」改目标重新规划。
3. **开始执行** → 弹窗自动关闭并跳到 **AI Operator** 三栏视图：Goal（目标）/ 执行态（步骤进度）/ AI Activity（事件人话流，含「AI 已自动恢复」teal 事件）。

**高级选项**（折叠）：

| 选项 | 说明 |
| --- | --- |
| 浏览器环境 | 指定用哪个 Profile 执行；留空 = 自动选择。只有一个 Profile 时自动带上 |
| 执行模式 | **自主模式**——AI 全程执行，高风险动作才询问；**协助模式**——每一步都要你确认；**演练模式**——只规划不执行；**调试模式**——逐步排查用 |

规划或启动失败时，错误会以顶部 toast 提示（不会白屏、不会丢已输入的目标）；任务创建成功后即使关掉弹窗，任务仍在 Tasks / AI Operator 中继续运行。

## 1. 就绪检查（第一次打开控制台）

控制台启动后会自动跑一遍就绪度自检；必需项缺失时会**自动落到「就绪检查」页**，不需要你猜缺什么。

| 类别 | 检查项 | 未通过时 |
|------|--------|----------|
| 必需 | 身份会话 | 本机模式自动引导（绿）；多用户模式自动弹出**登录页**（见下） |
| 必需 | LLM 凭据 | 「系统设置 → LLM」填 provider + Key → 点「测试连通」 |
| 必需 | 浏览器配置 | 「配置管理」新建配置 |
| 可选 | 指纹模板 / 代理 / 自动化任务 | 缺失不影响启动，只影响对应能力 |

- 右上角徽标常驻显示状态：`● 就绪`（绿）/ `● 待引导`（琥珀，悬停看阻塞清单）。
- 处理完回到该页点「重新检查」，三必需项全绿即可投入日常使用。
- 机读口径：`GET /api/settings/readiness` → `stage: READY | SETUP_REQUIRED`。

### 1.1 多用户模式登录（C49）

服务器以 `FPB_API_TOKEN` 部署（共享/远程访问）时，浏览器打开控制台会**自动弹出全屏登录页**：

- **登录**：输入用户名与密码 → 登录后进入控制台，会话凭据保存在本机浏览器（localStorage）。
- **注册**：用户名 ≥3 字符（仅字母数字 `_.-`）、密码 ≥8 位；注册即获个人工作区（OWNER 角色）。跨工作区授权由管理员在「治理中心」分配。
- **退出登录**：右上角「退出登录」按钮（仅会话模式显示）→ 结束会话并返回登录页；会话过期（API 返回 401）也会自动回到登录页。
- **本机单机模式**（默认，loopback 访问）永远不会弹出登录页，行为与之前完全一致。

## 2. 配置管理（浏览器身份）

一个 **Profile = 一套独立浏览器身份**（指纹 + Cookie 存储 + 代理绑定）。

**建配置**：新建 → 起名 → 选 OS/浏览器基线 →（可选）绑定代理与模板 → 保存。指纹由 seed 派生、可复现；每次启动同一 seed 得到同一指纹。

**启动浏览器**：列表行「启动」→ 有 headful（真实分辨率）与 headless 两种形态；启动后自动做三件事：伪造 UA 版本对齐本机引擎版本、捕获原生 brands 做 UA-CH 回放、生成 profile 级 identity.json。

**其他操作**：
- 「画面」：实时查看浏览器画面——默认 CDP 实时流（≈8fps，页面静止时零流量）；断线自动降级 2.5s 低速截图轮询并提示，浏览器停止后流自动断开。
- 「完整性」：启动前一致性体检（UA ↔ brands ↔ 引擎版本对账），只报警不阻断。
- 「复制」：克隆配置并强制换 seed（杜绝整批同指纹）。
- 「导入/导出」：JSON 互迁，凭据**不在**导出文件内。
- 「运行态」：查看活跃会话（时长 / 当前页面 / 页签数 / 代理）。

**指纹细节**：UA/UA-CH、screen、时区、语言、字体、WebGL、Canvas、Audio、硬件并发、内存、触点全部可覆写；留空则按 seed 派生。语言走 CONFIG 层 pref 注入（三端同源：window / Worker / HTTP）。

## 3. 指纹模板

把「稳定字段」钉住的指纹基线。配合**批量建号**：同模板 + 每号独立 seed（「同形不同样」）。模板强制忽略调用方传入的 seed。典型用法：先手调一份满意的基础指纹存模板，之后批量建号都挂它。

## 4. 代理管理

- 支持 HTTP / SOCKS5；带认证的 SOCKS5 自动走本地 shim 中转。
- 「健康检查」：测延迟与出口 IP；「Geo」：查出口 IP 的国家/ISP/是否机房。
- **代理-指纹一致性**：绑定代理后，时区/语言/地理可按出口 IP 自动推导（timezoneMode/languageMode=ip），避免「美国 IP + 北京时区」这种硬伤。
- 出口预检会在启动时提示脏 IP（机房 IP、Google 不可达等），只报警不改启动行为。

## 5. 加密保险库

邮箱/密码/卡号/CVV 的 AES-256-GCM 加密存储（主密钥 `FPB_MASTER_KEY`，start.bat 首启自动生成并写入 .env）。

- AI 任务里凭据以 **credentialRef（引用）** 传用：LLM 全程只见掩码（如 `****2164`），永不见明文 CVV/卡号/密码——这是产品红线，不是可选项。
- GET 接口只回掩码；导出包/备份里凭据独立加密路径。
- **已保存凭据只回显掩码（C98）**：编辑配置时已保存的凭据字段显示为掩码而非明文，也不回传明文——因此表单里凭据字段为空**不代表数据丢失**；只有字段旁的掩码回显才是已存内容的权威提示。
- **保存失败内联持久化（C98）**：凭据保存失败时错误提示固定内联显示在表单内，不会自动消失；修复问题（如网络/权限）后重试即可，成功后错误提示自动清除。

## 6. 自动化任务（AI 操作员）

- 「AI 操作员」页直接对话式下任务（例：「去 xx 站搜无线鼠标，把销量第一加购」），服务端走 Planner→Runtime→Verification→Repair→Escalation 全链。
- 「自动化任务」页看任务列表与状态；点进详情有**取证四件套**：
  - **诊断**：根因 / 类别 / 置信度 / 重试策略 / 证据链 / 失败时刻快照；
  - **修复尝试**：每次 repair 的动作与结果 + 各策略历史成功率；
  - **执行记录**：实际执行链；
  - **动作链重放**：逐步骤回放 AI 做了什么（JsonBlock 可展开原始取证 JSON）。
- 任务级操作：启动 / 暂停 / 恢复 / 取消 / 重试 / 审批（ESCALATION 任务需人工 approve/reject）。
- **崩溃恢复（recover）**：进程崩溃或服务重启后，在任务详情一键从 checkpoint 重建执行（自动跳过已成功步骤）；仅 RUNNING / HEALING / RECOVERING 状态可恢复。
- **目标保真（C96）**：你在对话框里输入的目标与网址在规划重试全程保持不变——不会出现「明明说的是 A 站，计划里却写着别的网址」。

### 6.1 为什么任务会交给人（凭据授权闸 + 诊断门）

任务转 HUMAN_ESCALATION 不是失败重试，而是安全设计的显式交人。两类常见原因：

**凭据授权闸（fail-closed）**：AI 执行填密码/支付类动作前，服务端先校验「这个任务 → 这条授权流程 → 这个目标站点」的授权链。**无法证明授权就一律拒绝**（跨站漂移、挑战页、无法解析目标 origin 等都算无法证明），任务立即转人工（终态原因 `CREDENTIAL_ACTION_BLOCKED`），**不会重试也不会自动修复**——AI 永远不会为了「完成填表」去绕过这道闸。处置：在任务详情确认目标网址与凭据归属一致后 approve（人工接管）或 reject（终止）。

**诊断门（六态判定）**：执行中遇到异常页面状态时，服务端先判定属于哪一类再决定动作，避免盲目重试：

| 诊断态 | 含义（用户视角） | 系统行为 |
|--------|------------------|----------|
| TARGET_NOT_PRESENT_YET | 目标还没渲染出来（刚提交，页面在路上） | 短暂等待后重观察，可继续推进 |
| MULTI_STEP_FORM | 多步表单（当前步成功，下一步还没出现） | 同上，正常分步推进 |
| NAVIGATION_IN_PROGRESS | 页面正在跳转 | 等跳转完成再观察（最多 2 次，超过交人） |
| CROSS_ORIGIN_DRIFT | 页面被带到了**另一个站点**的凭据输入框 | **立即交人**，凭据动作绝不跨站执行 |
| SECURITY_CHALLENGE | 遇到验证码/风控挑战页 | **立即交人**（产品不做挑战绕过） |
| TARGET_STALE | 之前定位的元素已失效 | 重新观察定位，可继续推进 |

**规划失败持久展示（C97）**：任务创建弹窗里规划失败时，失败原因会**持久内联显示**并伴随加载指示，不会一闪而过让你以为点了没反应。

## 7. 定时调度

- 固定间隔 或 cron 表达式（5 字段，按表触发不漂移；支持 `@daily` 等别名）。
- 调度触发的任务与手跑完全同链路；任务时间线可从 Observability 看。

## 8. 执行引擎

| 区块 | 用途 |
|------|------|
| 派遣调度器 | 启动/暂停/恢复/排水/停止/**单次 tick**（手动推一拍，验证调度是否活着） |
| Worker 池 | 启动新 Worker；优雅停止（DRAINING：等当前任务收尾）；DEAD 自动标红 |
| 队列 | 基础队列 + 派遣记录（QUEUED → RUNNING → 终态） |
| 资源池 | 浏览器资源获取/释放；**僵尸资源回收**：心跳超时或任务已终态仍占着的绑定一键回收（超时可调，默认 30s） |
| 提交执行 | taskId 直接入队：调度器运行中→队列派遣；未运行→直接经唯一执行链启动（绝不卡 QUEUED） |
| 崩溃恢复扫描 | DEAD worker 上残留的 RUNNING 执行 → RECOVERING，可重派 |
| 契约/策略调试 | 粘贴动作 JSON，只读跑 schema 校验 + policy 判定（不执行）。注意：`click` 等 MUST_VERIFY 动作必须自带 `verification`（type≠none）或 `expectedBusinessState`，否则不合法 |

## 9. 智能记忆

- **只读知识面**：站点画像 / 元素记忆 / 流记忆 / 失败知识——AI 跑得越多这里越厚。
- **经验包**：一键导出/导入站点经验（跨环境迁移，例如把开发机积累的站点记忆带到部署机）。
- **决策试算**：输入 URL dry-run Router 决策与环境推荐，不真启动。
- **健康看板**：Router 准确率 / LLM 节省 / Memory ROI / 弱项列表；环境评分表支持手动登记任务结果；站点×环境矩阵一眼看出哪个站在哪种环境上还跑不动。

## 10. 治理中心

- **API Keys**：创建时明文**只出现一次**（含复制按钮），之后只回掩码；可标记只读（只读 key 一切写操作 403）、随时撤销即失效。
- **审计日志**：只写不可篡改的安全事件流；支持过滤与 JSON 导出。
- **工作空间 / 成员**：RBAC（OWNER/ADMIN/MEMBER…），成员按角色继承权限；资源按工作空间隔离。
- **凭据引用（credentialRef）**：治理卡只登记 profileId + 类型 + 站点 + 标签（列表永远是脱敏视图，不含明文）；明文只在对应 Profile 编辑器的 Account 页签维护，可用性按保险库实时现算。删除引用不影响已加密的明文本身。

## 11. Observability

- Dashboard：任务状态分布、成功率、耗时、ESCALATION 占比。
- Deprecation 卡：遗留端点（/ai/queue、/ai/events 等）的命中计数与最近调用者，支撑安全下线决策（RFC 8594）。
- Trace：单任务时间线（VIL 节点、修复、**恢复成功（RECOVERY：动作/观测次数/耗时）**、升级决策），可与任务详情取证互跳。

## 12. 系统设置

- **LLM**：provider / model / baseUrl / API Key。Key 保存即加密落盘，运行时即时生效（applyToEnv），改完无需重启；「测试连通」直测 provider。
- **env 对账**：只读展示 .env / 进程注入 / settings 覆盖三者的实际生效值。
- **数据备份**：一键导出全量快照（含 vault 独立加密路径，不含 node_modules）；恢复前自动做防呆快照，带白名单与版本校验。恢复为两步确认：选择文件先本地解析校验并挂起（不发请求），需再点「确认恢复」才执行。
- **存储使用与清理**：四类目录体积统计（.benchmark 回归日志 / data/profiles 浏览器数据 / data 业务集合 / client/dist，结果缓存 5 分钟）。清理只走白名单（回归日志保留最近 3 个；未运行 profile 的浏览器数据），先「清理预览」（dry-run，不删任何文件）再「确认清理」两步执行；**业务数据集合永不参与清理**。⚠️ profile 项包含其 Cookie/登录态，确认前看清预览清单；运行中的 profile 自动跳过。

## 13. 常见工作流

**A. 建号 → 代理 → 首次启动**
1. 代理管理添加并做 Geo 检查 → 2. 配置管理新建配置并绑定代理（时区/语言选 ip 模式）→ 3. 启动 → 4. 就绪检查应全绿。

**B. 让 AI 干活**
1. 确认 LLM 凭据绿 → 2. AI 操作员下发任务（凭据用保险库引用，不贴明文）→ 3. 任务详情盯诊断与重放 → 4. 跑顺后挂定时调度。

**C. 跨机器迁移**
1. 旧机：备份导出 + 经验包导出 → 2. 新机：解压发布包双击 start.bat → 3. 系统设置配 Key → 备份恢复 + 经验包导入 → 4. 就绪检查全绿。

**D. 服务崩了怎么救**
1. 重启 server（执行引擎状态持久化，QUEUED 任务还在）→ 2. 执行引擎「崩溃恢复扫描」回收 DEAD 残留 → 3. 「僵尸资源回收」清理泄漏绑定 → 4. 观察单次 tick 是否推进；中断任务在详情页点「崩溃恢复」从 checkpoint 续跑。

**E. 磁盘占用越来越大**
1. 系统设置 → 存储使用看四类目录体积 → 2. 「清理预览」核对清单（⚠️ profile 项含登录态）→ 3. 「确认清理」；回归日志只留最近 3 个，业务数据集合不受影响。

## 14. FAQ

- **Key 填在哪？** 推荐「系统设置」面板（加密落盘+即时生效）；.env 也可（`DEEPSEEK_API_KEY`），settings 覆盖 .env。
- **面板报「凭据不可用 / 加密失败」？** `FPB_MASTER_KEY` 缺失。start.bat 会自动生成；手动跑则自行生成 32 字节 base64 写入 .env。
- **AI 任务卡 QUEUED？** 调度器没启动——执行引擎点「启动」；或直接「提交执行」（未运行时会走直接执行链）。
- **浏览器起不来？** 先跑 `npx playwright install chromium`；再看完整性体检告警与代理 shim 日志。
- **两个环境指纹不一致？** identity.json 是 profile 级持久身份（同 seed 跨启动稳定）；确认没有手改 fingerprintOverride 的稳定字段。
- **就绪检查一直「待引导」？** 看右上角徽标悬停清单，三个必需项挨个处理。
- **清理预览里的 profile 项能直接删吗？** 先想清楚——未运行 profile 的浏览器数据包含其 Cookie/登录态/会话，确属废弃号再确认；运行中的 profile 自动跳过，业务数据集合永不参与。
- **浮层关不掉？** 任意浮层（任务详情 / 浏览器画面 / 配置编辑）按 Esc 即关闭；确认弹窗按 Esc 等于取消（不会误确认）。

## 15. 安全红线（内置，不可配置关闭）

- LLM 永不见明文 CVV/卡号/密码（credentialRef + masked）。
- **凭据动作授权闸 fail-closed**：凭据类动作前强制校验任务→授权流程→目标 origin 的授权链；无法证明授权（含跨 origin、挑战页、origin 不可解析）一律拒绝并直接转人工，不可配置关闭，AI 无绕过路径。

- API Key 明文只在创建响应出现一次；只读 key 写操作 403；身份自管端点拒绝一切 API Key 写（防自举提权）。
- 对外部署必须显式 `FPB_BIND` + `FPB_API_TOKEN`；不安全组合启动期直接拒绝（fail-fast，不静默降级）。
